# Scene03 v10｜隊列確認・静止シーンの走路統一

実施日：2026-10-30

## 不具合の原因と対処

v9ではアニメーション中の走路だけJRA公式コース図を基にした修正済みカーブになっていた。一方、静止「コーナー進入前。隊列を確認。」では app.js / cinematic.js に残っていた固定の reviewTerrain が呼ばれ、東京・中山の両方で古い汎用曲線を描画していた。

v10の jra_geometry_v10.js は reviewTerrain を修正し、実際のアニメーション用の terrainModel と terrainGrain をSVGノードとして再利用する。独立した静止用曲線を描かない。SVGのviewBoxもアニメーションと同じ 1080×555 に合わせる。静止用SVGパターン定義は別IDを利用し、ID競合を回避した。

このためコース変更・芝/ダート切替・左右回り変更時にも、動画と静止画の走路が同じデータを参照する。先頭候補、予想判断、馬名、馬番、ナレーション、起伏データは変更しない。

## 検証（実Chrome）

- 東京ダート1400m：16頭、左カーブの走路と静止画が同じSVG座標（内外2ラチとも完全一致）。
- 中山芝2000m・A：12頭、右カーブの走路と静止画が同じSVG座標（内外2ラチとも完全一致）。
- アニメーションの終了位置と静止後の馬番の数値座標が一致。全馬0.02px以内。
- actionSvg/reviewSvg の viewBox はどちらも 0 0 1080 555。
- 静止SVGの路面テクスチャと参照パターンが存在し、エラーなし。
- 既存QA：東京・中山の動作、モバイル表示、坂HUDの同期、コースマスタv5の参照を確認。
- 実画面：review_same_curve_tokyo_v10.png、review_same_curve_nakayama_v10.png。
- 修正前後比較：review_before_after_v10.jpg。

## 制限・運用

JRA公式図を手動トレースした形状は測量GISではなく、馬ごとの想定進路はデモ。今回の修正は動画と静止画の描画不整合を直すだけで、公式コースマスタ・KBV本番予想へは変更を加えていない。

開発ブランチ work/scene03-cinematic-polish の vnext-v10 内にのみ保存。課題ブランチ・main・既存Pagesサイトはユーザーの明示的な依頼なしに更新しない。

## 試し方

スマホで簡単に比較できるように、同じレースをA案→B案の順に流すMP4を `camera_ab_tokyo_v11.mp4` として付属する。**A/B各6.25秒、合計12.5秒の比較映像**。音声なし・試作用で、実際の競走速度や本番ナレーション尺を示すものではない。

`index.html` をローカルブラウザで開き、操作列の「A｜俯瞰」と「B｜追走」を押す。
再生位置とサンプルレースは変えずにカメラのみ切り替わる。
`?camera=follow` をURLに付けて開始してもよい。
東京ダート1400m／中山芝2000mのサンプル切替、WAV尺連動も元のまま。
動画出力用の固定秒数・実走GPS情報は一切追加していない。

## 比較内容

- A：全頭の位置関係を見渡す、最大約4.7%の抑えた俯瞰ズーム。
- B：既存の注目馬群へカメラを寄せる、最大約19%ズームと追尾パン。
- 両案とも、移動終盤に倍率1・移動量0へ戻し、v10で検証済みの停止画面に視覚的に繋げる。
- テスト画面内だけ、起伏HUDとコースミニ図を上へ移動して馬番被りを減らし、FORMATIONラベルを再配置。
- カメラは予想数値や馬ごとの表示座標を変更しない。

## QA

`qa_camera_v11.cjs` はPuppeteerを用いた再現可能なブラウザテスト。
東京16頭・中山12頭について次を検証する：
A/Bカメラに差がある、同じ再生時刻で全頭の表示座標が一致、
両案の最終カメラが恒等変換へ戻る、停止画面と動画の走路モデルが共有される、
SVG viewBox一致、ブラウザ例外なし。

QA結果は `qa_camera_v11_results.json`、比較静止画は `qa_{tokyo|nakayama}_{overview|follow}_v11.png`。
なお画像はアクション途中の1フレームであり、アニメーション全体の視聴テストに代わるものではない。

# Scene03 v13 ― 新DB連携・汎用アニメーション試作

## 状態

**開発用の実働プロトタイプ。正式Scene03へ未統合。**
ブランチ `work/scene03-generic-animation-v13` は `work/scene03-material-comparison-v12` から分岐。
従来の `vnext-v10/`, `vnext-v11/`, `vnext-v12/`、main、既存Pages、KBV正本SQLiteは変更しない。

## 目的

各レースで使い回すScene03として、**コース情報・レース情報・隊列入力を分離**。
同じ描画エンジンがコース形状、枠色、頭数、注目馬、移動位置、起伏グラフを入力ごとに作る。

アニメーションの順序：
1. コース全景（スタートと最初のコーナーの位置を確認）
2. 断面図の概略（コースを走る光点と起伏グラフ）
3. ゲート付近から予想の隊列を組み立てる模式アニメーション
4. 全頭の想定位置で静止し、展開を確認

ページの操作：レース選択、再生/一時停止、スクラブ、セクション移動、レースJSON読込。
`engine.js`内のコースコード・馬名・馬番は固定せず、JSON入力から生成する。

## 新DBの利用

唯一の正本SQLite `C:\KBV\qa_incremental_20261027\kbv_work.sqlite` を `mode=ro` + `PRAGMA query_only=ON` で調査。
型付き `jv_r_CS` の競馬場コード `f004`、距離 `f005`、トラックコード `f006`、改修日 `f007`、説明 `f008` を利用。
実DBレコード数119、場×距離×トラックの重複除外117キー（歴史的な設定も含む。現在使用される全条件の数ではない）。
**公衆向けGitHubにはJV-DataのCS全文を配置せず**、限定した検証済み事実の短い要約・キー・原本IDのみを `db_cs_snapshot.json` に格納。

実デモ：
- 東京ダート1400m（16頭・左回り）：CS raw_event_id 42／作成日2016-07-21
- 中山芝2000m A（12頭・右回り）：CS raw_event_id 58／作成日2015-04-08

**CSは文章コース説明であり、測量GPS・曲率・各地点の標高座標ではない。**
コース平面図・断面図は旧v10でJRA公開図を手動トレースした概略モデルを使う。
横座標・標高の1対1対応／Z倍率の測量認証は未実施。高低断面グラフも「概略」で、現実の勾配を計測した図とは断言しない。
現在の改修状態・JRA現行図との再照合も正式運用前の必須条件。

## 汎用化・サポート範囲

同じエンジンで東京16頭、中山12頭、東京8頭（番号飛び）、東京18頭をQAで実行済み。
入力は `sample_races.json` のような race JSON。

- `courseId` は `course_catalog.json` と `course_geometry.json` に明示登録した条件に限る。
- `runners` は馬番・名前・枠番・正規化済み想定位置 `formation.progress/lane` を持つ（1～18頭）。
- `focusNumbers` は任意の注目馬番配列（空配列可）。
- 未登録コース、不正位置、不正枠、重複馬番、出典の違うCS情報を暗黙の代替図で埋めない（fail-fast）。

**現状、詳細な3Dコース形状の登録は2条件のみ**。CSの117キー中、残り115キーの形状が自動で生成できるわけではない。
別のレースでも同一コース条件なら差し替えて利用可能だが、「JRAすべてのレースに対応完了」とは言わない。
必要な距離・トラック・回り・芝コース区分ごとに公式形状と起伏資料の整備・照合が必要。
また2026年の実PS1/PS2/PS3から当該JSONへの正式変換は未接続。v10から既存の表示テスト入力を再利用しており、レース予想の正式認証とは無関係。

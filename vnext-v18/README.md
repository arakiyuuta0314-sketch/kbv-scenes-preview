# Scene03 v18｜曲線走路での隊列形成とWAV実尺タイムライン

作業ブランチ：`work/scene03-track-path-audio-timing-v18`。本番未採用・独立試作。

## 今回の対応

**1. 「中山が直線レースに見える」問題の修正**

v17は馬番の移動を `startF + distanceToFirstCorner * u` で行っていたため、**スタートから最初のコーナーまでの短い範囲に限定されていた**。

v18では、各コースに共通する走行距離インターフェースを設け、`startFraction + travelMeters/lapMeters` を周回走路の曲線上へ写像する。東京・中山の双方で、最初のコーナーを超えてその先の曲線上まで進む。

- 東京ダート1400m（16頭）：スタートから3コーナーまで約440m → 先頭グループの確認位置は概算660m付近
- 中山芝2000m A（12頭）：スタートから1コーナーまで約405m → 確認位置は概算625m付近
- 頭数・並び入力に応じて、各馬の進行距離と内外位置を描画。頭数に依存する専用コードは使わない。
- 物理的な平均速度や着順の再演ではなく、**序盤の隊列形成を見せる模式アニメーション**。全レースの走行完了は表現しない。
- 馬は同じ走路に沿って前進し、曲がり角の先でレビュー時に静止。移動距離は単調増加、レビュー状態は固定。
- カメラは馬群の移動位置へ遅れて追従し、中盤に画面外へ出ないようにする。説明区間ではv17同様にコース全景を維持する。

数値で確認：中山の走路トレースから求めた初コーナー位置は約418mに相当し、CS記述上の約405mとは約13mの差がある。どちらかを実測値だと断定せず、**手動トレース由来の未認証誤差**として明示する。東京は約440.2m vs 約440m。高低差の位置／平面形状の公式再認証は継続課題。

**2. ナレーション尺と映像の切替を分離**

正本素材 `03_scene3.wav` を**読み取り専用**で解析したところ、2026-11-01の共有素材のPCM情報は24kHz／モノラル／16bit／858,624フレーム＝**35.776秒**。ただし、このWAVがv18に付属する東京・中山の表示テスト入力と同じレースであることは未検証。

`build_wav_cue_sheet.py` が、実WAVのヘッダーから長さを取得し、**人間が音声を聞いて確認した発話時刻**のJSONと照合して、その時刻表を作る。WAVから内容や話した言葉の位置を推測しない。欠損や並び不正、前後矛盾はfail-fast。

ブラウザ側は `timing.mjs` を使用する。例：
```json
{
  "scene03": {
    "cueSheet": {
      "durationSec": 35.776,
      "alignmentStatus": "USER_CONFIRMED_TIMESTAMPS",
      "confirmationSource": "final narration script + WAV listening confirmation",
      "events": [
        {"atSec": 0, "stage": "formation", "page": 0},
        {"atSec": 8.0, "stage": "formation", "page": 1},
        {"atSec": 18.0, "stage": "review", "page": 0},
        {"atSec": 23.0, "stage": "review", "page": 1, "focusNumbers": [3, 5], "headline": "確認した短い字幕"},
        {"atSec": 30.0, "stage": "review", "page": 1, "focusNumbers": [12], "headline": "次の説明"}
      ]
    }
  }
}
```
**上記の時刻と字幕はスキーマ例だけであり、実WAVの音声に合うと確認したものではない。** 本番で `USER_CONFIRMED_TIMESTAMPS` を付けるには実際の台本・WAVと照合する。ラベルを自動で付け替える処理はない。

ナレーションが隊列の話だけなら `course` / `slope` の説明区間をスキップできる。長尺の隊列説明に対応するため、同じ `review` ページ内で馬番ごとに説明時刻を複数設けることが可能。必要な馬番だけを順に大きくする。

下記は**未同期デモ**：
- 22秒／38秒／60秒のステージ時間配分テスト
- 実WAVの**尺だけ**を使用した35.776秒のデモ（`wav35_demo_cues.json`）
- 35.776秒のデモ時刻 `0 / 10 / 19 / 27秒` は発話内容を聴き取って確定した値**ではない**。
- 馬群の動きは約6秒で自然に終わり、ナレーションが続けば動きを保持。22/60秒で最終位置が一致する。

## 使用上の制約

- 現在の詳細コース幾何は東京D1400、中山芝2000Aの2条件のみ。他コースの架空楕円や起伏の推測生成はしない。
- 走路形状・各点の高さはJRA公式図の人手トレースに基づく概略。新JV-CSはコース説明文と区分であり測量3Dではない。JRA公式図と距離・傾斜を完全照合した状態ではない。
- `sample_races.json` の馬番と隊列は表示試験用データで、正式なPhase1/PS3の値ではない。
- 動画の発話同期には**正確な最終ナレーション原稿、対象レースと一致するWAV、発話位置の確認済み時刻**が必要。これらの1対1照合は今回未完成。
- ローカルで `python -m http.server 8771`、 `http://127.0.0.1:8771/vnext-v18/` を開く。実iPhoneでのブラウザ表示は未検証。
- 過去のv10〜v17・main・既存GitHub Pages・正本SQLiteは変更していない。

## 運用前に必要なこと

正式動画では、確定台本から『この発話の開始で表示を切り替える』を定義し、音声で実測して時刻を確定させる。台本が変わればタイムラインも更新し、同じ識別子／WAV／PICKを参照していることを確認してから書き出す。KBVの公式コース形状拡充と正確な高低データの再認証も必要。

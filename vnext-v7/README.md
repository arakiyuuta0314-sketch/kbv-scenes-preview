# KBV Scene03｜地形・馬群の連動試作 v7

更新：2026-10-30。これは **Web / DaVinci本番に未採用の試作**。既存公開サイト、KBV本体を変更しない。

## 今回改善したところ

- 発走〜最初のコーナーに至る馬番の通過位置は **JRAコース図からトレースした中心線** と結び、各馬の予測した進路位置を沿わせる。途中フレームをゲートと最終座標の直線補間で描く方式を廃止。
- コース全体の位置図と、上り・下りの概略断面HUDの移動位置を **同一の「先頭想定馬の区間内位置」** に連動。
- 東京ダート1400mの16頭と中山芝2000m（Aコース・架空12頭）で、発走→隊列形成→静止解説を検証。
- 馬番が隠れる可能性のある現在位置ミニ図は、スタート直後に隠す。停止解説への切替時にマーカー座標が移動しない。
- 各レースはレースJSONにより、馬名・枠・頭数・予測前後位置・内外想定・説明文が可変。芝/ダート、内外回りはコースIDに基づく。欠損・未知コースはfail-fast。
- **ナレーションの秒数は固定しない。** WAVファイルを与えるとその長さを映像全体の尺に採用。場面割合は説明文の文字数比で計算（発話位置の厳密同期は未実装）。

## KBV予想への安全な接続準備

`course_facts_v7.js` は `KBV_TERRAIN_FACTS_V7.fromRace(race)` を提供し、コースマスタ照合後に **公式資料に裏付けのある事実のみ** を返す。

出力の主なキー：`schema=kbv.terrain-facts/v1`、`status=FACTS_ONLY_NO_SCORE`、`courseIdentity`、`facts.firstTurnDistanceM`、`facts.qualitative`、`exclusions`。

意図的な除外：
- 仮の馬群配置・想定ラップ・動画再生時間
- コース図からの概略画素座標・標高サンプリング
- 坂の実距離別勾配・馬ごとの負荷・PICKスコア

`terrain_facts_sample_v7.json` は東京と中山の出力サンプル。**KBV本番の判定、Phase1・Phase2、PICKは一切変更していない。** 実際の展開予想への効果はバックテスト前には未検証。

## 残る重要課題

1. 実測地形としての精度向上には測量済み標高・内外ラチ座標が必要。図面トレースを「正確な測量3D」とは呼ばない。
2. 今の隊列データはデモであり、実際のKBV `pick_material.json` や予想確定出力から自動取り込みする接続は未実装。
3. ナレーションの語句と字幕・馬群の強調切替を正確に合わせる仕組み、MP4レンダリング、DaVinci Resolveとの統合は未実装。
4. 公式コースマスタは134条件を認識するが、高詳細の走路モデルを用意したのは東京ダ1400m、中山芝2000m（A）の2条件だけ。未登録は表示せず明示的に停止する。
